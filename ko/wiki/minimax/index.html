MiniMax(미니맥스)

다른 이름: minimaxMiniMax미니맥스

MiniMax는 M2 텍스트 모델, Hailuo 비디오, Speech·Music 모델, MiniMax Agent, 개발자 API를 함께 운영하는 중국 AI 랩 겸 브랜드 이름이야. 그래서 M2.7 같은 개별 모델명보다 한 단계 위 이름으로 읽는 편이 맞아.

한 줄 정의

MiniMax는 중국 AI 랩 겸 브랜드 이름이야. AIKI 위키에서는 보통 MiniMax M2.7 같은 개별 텍스트 모델 하나를 뜻하기보다, M2 텍스트 모델 계열과 Hailuo 비디오, Speech·Music 모델, MiniMax Agent, 개발자 API를 함께 운영하는 상위 이름으로 읽는 편이 맞아.

2026년 3월 18일 공식 발표도 이 층위를 분명히 보여 줘. 발표문은 M2.7을 MiniMax가 내놓은 새 텍스트 모델로 소개하고, 여러 에이전트를 묶는 협업 구조, 복잡한 스킬 묶음, 상황에 맞는 도구 탐색 같은 방향을 밀고 있다고 적어. 그러니까 MiniMax가 강하다라는 문장을 보면, 먼저 회사 전체의 모델 전략을 말하는지, 아니면 M2.7 같은 개별 모델 성능을 말하는지부터 갈라 읽어야 해.

어떻게 작동하나

실무에서 MiniMax는 보통 아래 세 층위로 읽으면 정리가 돼.

  • 브랜드 레이어: 공식 사이트는 텍스트, 음성, 비디오 Hailuo, 음악, Agent, API를 한 묶음으로 보여 줘. 그래서 MiniMax만 써도 회사와 제품군을 같이 가리키는 경우가 많아.
  • 개별 모델 레이어: 2026년 3월 18일 발표문과 2026년 5월 3일 API 문서는 MiniMax-M2.7과 M2.7-highspeed를 따로 적고, 컨텍스트 윈도도 둘 다 204,800으로 안내해.
  • 접근 경로 레이어: 같은 M2.7을 API로도 쓰고 Hugging Face 가중치로도 다루게 해 둬서, 서비스형 사용과 Local LLM 배포가 한 브랜드 아래에 같이 붙어 있어.

여기서 MiniMax M2.7은 MiniMax 전체와 같은 말이 아니야. M2.7은 그 아래에 붙는 개별 텍스트 모델이고, MiniMax는 그 모델을 포함한 상위 이름이야. 또 MiniMax 자체가 Agentic Coding이라는 개념은 아니고, 그 방향을 강하게 미는 모델과 제품군을 묶는 이름에 가깝지.

Hugging Face의 MiniMaxAI/MiniMax-M2.7 모델 카드는 모델 크기를 229B params로 적고 있고, API 문서는 Token Plan과 연결된 서비스형 접근을 같이 보여 줘. 그래서 MiniMax는 챗봇 앱 하나로 닫힌 이름이라기보다, 모델 배포와 제품 배포가 같이 붙어 움직이는 이름으로 보는 편이 더 정확해.

왜 중요한가

이 이름이 중요한 이유는 숫자 하나만 보고 판단하면 층위를 자주 헷갈리기 때문이야. 예를 들어 M2.7 발표문에는 SWE-Pro 56.22, VIBE-Pro 55.6, Terminal Bench 2.0 57.0, GDPval-AA 1495 같은 수치가 붙어 있어. 그런데 그 숫자는 MiniMax 전체 기업 평가가 아니라 M2.7이라는 특정 모델 버전에 붙은 성능 신호야. 반대로 Token Plan 문서의 Starter 1,500회/5시간, Plus 4,500회/5시간, Max 15,000회/5시간은 모델 성능이 아니라 서비스 접근 조건에 더 가까워.

정리하면 이렇게 읽는 편이 덜 헷갈려.

  • MiniMax M2.7: 개별 모델 페이지
  • Local LLM: 실행 방식 이름
  • License: 배포와 상업 사용 조건
  • MiniMax: 그 셋을 감싸는 공급자·브랜드 이름

이 구분이 서야 로컬로 돌릴지 API로 붙일지, 또는 단순 채팅보다 긴 에이전트 작업에 맞는지까지 한 번에 정리돼.

주의해서 볼 점

MiniMax를 통째로 오픈 웨이트 랩이라고 읽으면 절반만 맞아. M2.7처럼 Hugging Face에 공개된 가중치도 있지만, 실제 사용 경로는 API 문서와 Token Plan처럼 서비스형 접근이 같이 크고, 모델마다 License와 배포 조건도 달라질 수 있어. 그래서 MiniMax가 공개됐다는 문장을 보면, 회사 얘기인지 M2.7 같은 개별 모델 공개인지, 아니면 API 플랜 확장인지 날짜와 대상을 같이 확인하는 편이 안전해.

커뮤니티 문맥도 층위를 섞기 쉬워. 예를 들어 2026년 4월 12일 LocalLLaMA의 한 스레드는 MiniMax를 다른 중국 랩들과 함께 묶어 최신 모델 공개가 왜 늦어지느냐는 불만 쪽에서 다뤘어. 하지만 공식 문서 기준으로는 공개 가중치, API 구독, 에이전트 제품이 한 이름 아래에 동시에 붙어 있어. 그래서 MiniMax라는 단어는 성능표 하나보다 어느 레이어의 얘기인가를 먼저 확인하게 만드는 표식에 가깝다.

통과 원문 대조 검증 출처 5
MiniMax를 모델 하나 이름으로 보면 자꾸 헷갈려서, 공식 사이트와 문서가 이 이름을 어떻게 쓰는지 먼저 맞춰 봤어.
  • 독자 문제 대조: `MiniMax가 세다`가 회사 얘긴지, M2.7 같은 개별 모델 얘긴지, 아니면 API 상품 얘긴지 먼저 헷갈리니까 그 문제부터 잡았어.
  • 공식 사이트는 텍스트 모델(M2.7, M2.5, M2.1), 음성, 비디오 Hailuo, 음악, Agent, API를 한 브랜드 아래에서 같이 보여 줘.
  • 2026년 3월 18일 M2.7 발표문은 M2.7을 MiniMax의 개별 텍스트 모델로 설명하니까, minimax와 minimax-m2.7을 같은 층위로 쓰면 안 돼.
  • API 문서는 MiniMax-M2.7과 M2.7-highspeed를 따로 적고 있어서, MiniMax 자체가 곧 모델 버전명은 아니라는 점도 다시 확인했어.
  • 이 페이지는 개별 모델 소개보다 상위 브랜드·생태계 설명에 초점을 두는 편이 덜 겹쳐.
통과 교차 검증 검증 출처 5
공식 사이트, 발표문, Hugging Face 모델 카드, API 문서를 같이 놓고 MiniMax가 어느 레이어 이름인지 교차로 봤어.
  • 비교 기준: 브랜드 이름인지, 개별 모델명인지, 서비스 접근 경로인지 이 세 축으로 나눠서 봤어.
  • 공식 사이트와 M2.7 소개 페이지를 같이 보면 MiniMax는 회사/브랜드 이름이고 M2.7은 그 아래 텍스트 모델이라는 구도가 분명해.
  • Hugging Face에서는 MiniMaxAI/MiniMax-M2.7 [가중치](/ko/wiki/weight/)를 따로 배포하고, API 문서에서는 같은 모델을 서비스형 엔드포인트로도 제공해.
  • LocalLLaMA 스레드처럼 커뮤니티에서는 MiniMax를 `최근 공개 가중치 흐름` 문맥으로 많이 부르지만, 공식 문서 기준으로는 제품군과 접근 경로가 더 넓어.
  • 커뮤니티 체감은 보조 근거로만 쓰고, 모델명·접근 경로·성능 수치는 공식 문서를 기준으로 잡았어.
통과 수치 검증 검증 출처 4
본문 숫자는 모델 크기, 컨텍스트, 요청 한도처럼 공식 문서에서 바로 찍히는 것만 남겼어.
  • Hugging Face 모델 카드는 MiniMax-M2.7의 모델 크기를 229B params로 적고 있어.
  • 2026년 5월 3일 기준 Text Generation 문서는 MiniMax-M2.7과 M2.7-highspeed의 컨텍스트 윈도를 둘 다 204,800으로 안내해.
  • 같은 날짜 기준 Token Plan 문서는 M2.7 요청 한도를 Starter 1,500회/5시간, Plus 4,500회/5시간, Max 15,000회/5시간으로 적고 있어.
  • 2026년 3월 18일 M2.7 발표문은 SWE-Pro 56.22, VIBE-Pro 55.6, Terminal Bench 2 57.0, GDPval-AA 1495를 같이 제시해.
  • 변동이 큰 다운로드 수나 커뮤니티 반응 수치는 본문 핵심 판단 근거에서 뺐어.
통과 비판 검토 검증 출처 4
MiniMax를 곧바로 `오픈 모델 하나`나 `챗봇 앱 하나`로 읽는 오해를 막는 쪽으로 문장을 다시 점검했어.
  • MiniMax와 MiniMax M2.7을 분리해 적어서 브랜드 이름과 개별 모델명이 섞이지 않게 했어.
  • API 문서, Token Plan, Hugging Face 배포 경로를 같이 적어 로컬 배포와 서비스형 사용을 같은 말로 읽지 않게 했어.
  • 라이선스와 접근 경로가 모델마다 다를 수 있다는 경고를 넣어, MiniMax 전체를 단일 open-weight 정책으로 일반화하지 않게 했어.
  • 이 이름은 성능 비교보다도 `무슨 층위 얘긴가`를 먼저 가르는 데 더 쓸모가 있어.
