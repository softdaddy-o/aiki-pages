Workspace(워크스페이스)

다른 이름: workspaceWorkspace워크스페이스작업 공간

AI 제품에서 Workspace는 파일, 앱 연결, 공유 권한, 메모리, 에이전트 실행을 한 계정이나 팀 안에서 관리하는 작업 경계야. 채팅 답변이 업무 파일과 조직 권한으로 넘어가는 순간부터 이 말이 중요해져.

한 줄 정의

Workspace는 AI 제품에서 파일, 앱 연결, 공유 권한, 메모리, 실행 중인 Agent를 한 계정이나 팀 안에서 관리하는 작업 경계야. 그냥 대화창이 아니라, AI가 만든 결과가 문서, 시트, Slack 메시지, Drive 파일, 승인 절차로 넘어가는 자리라고 보면 돼.

이 말은 Google의 업무 앱 묶음 같은 제품군 이름으로도 쓰이고, ChatGPT에서 조직 안에 공유되는 팀 에이전트 기능 이름으로도 쓰여. 그래서 먼저 어느 층위인지 나눠야 해. 제품군인지, 계정 경계인지, 파일이 저장되는 공간인지, 에이전트가 권한을 받아 일하는 실행 공간인지가 다 달라.

어떻게 작동하나

Workspace는 보통 세 겹으로 움직여. 첫째는 파일과 문서야. Google의 공식 업무 앱 페이지는 Gmail, Google Drive, Meet, Chat, Calendar, Docs, Google Sheets, Slides, Gemini app 같은 앱을 한 업무 묶음으로 보여 줘. 이 안에서 파일은 혼자 보관하는 물건이 아니라, 소유자와 공유 권한, 댓글, 버전, 조직 관리 정책을 같이 받는 업무 단위가 돼.

둘째는 채팅 결과가 실제 파일로 바뀌는 흐름이야. Gemini는 2026년 4월 29일 업데이트로 채팅 안에서 Google Docs, Sheets, Slides 같은 Workspace 파일과 PDF, DOCX, Excel용 XLSX, CSV, LaTeX, TXT, RTF, Markdown 파일을 만들 수 있게 됐어. Google 발표 기준으로 대부분의 형식은 기기로 내려받거나 Drive로 내보낼 수 있고, 기능은 전 세계 Gemini 앱 사용자에게 제공돼. 채팅 답변을 복사해 문서로 옮기는 대신, 처음부터 업무 파일로 받는 쪽에 가까워진 거야.

셋째는 실행과 권한이야. OpenAI가 2026년 4월 22일 발표한 ChatGPT 팀 에이전트는 팀이 공유 에이전트를 만들고, 그 에이전트가 조직에서 정한 권한 안에서 보고서 작성, 코드 작업, 메시지 응답 같은 긴 작업을 처리하게 해. OpenAI 설명에 따르면 에이전트는 파일, 코드, 도구, 메모리를 쓸 수 있고, ChatGPT나 Slack에서 실행될 수 있어. Help Center 기준으로는 Google Calendar, Google Drive, Slack, SharePoint 같은 앱, custom MCP, 이미지 생성, 웹 검색 같은 도구도 에이전트 빌더에서 고를 수 있어.

왜 중요한가

Workspace가 중요한 이유는 AI 출력물이 개인 채팅에서 끝나지 않기 때문이야. 예를 들어 한 사람이 Gemini에게 예산안을 .xlsx로 만들게 하고 Drive에 저장하면, 그 순간부터 파일 권한, 공유 링크, 검산, 폴더 위치가 문제가 돼. PDF로 수업 자료를 만들거나 LaTeX로 스터디 가이드를 만들 때도 마찬가지야. 형식이 맞는 것과 내용이 맞는 건 다른 이야기야.

조직용 에이전트에서는 더 선명해져. OpenAI의 팀 에이전트가 Business, Enterprise, Edu, Teachers 플랜의 research preview에 들어간다고 해서 모든 조직에서 바로 같은 방식으로 켜지는 건 아니야. Enterprise 워크스페이스에서는 출시 시점에 기본으로 꺼져 있고 관리자가 켜야 하며, OpenAI 도움말은 EKM 고객에게는 제공되지 않는다고 제한해. 지원 플랜과 실제 사용 가능성을 분리해서 봐야 해.

실무에서는 질문이 이렇게 바뀌어. “AI가 파일을 만들 수 있나”보다 “그 파일이 어디에 저장되고 누가 볼 수 있나”가 먼저야. “에이전트가 Slack에서 답할 수 있나”보다 “어떤 앱 계정으로 인증하고, 쓰기 작업마다 승인을 요구하나”가 먼저야. Workspace는 이 질문들을 한데 묶어 주는 말이야.

주의해서 볼 점

먼저 같은 단어를 같은 제품으로 합치지 않는 게 좋아. Google의 업무 앱 묶음, Slack 조직 공간, ChatGPT 조직 계정은 모두 workspace라는 말을 쓰지만 관리 경계가 달라. 이름이 같다고 데이터 보관, 관리자 권한, 앱 연결 방식이 같아지는 건 아니야.

파일 생성도 과하게 기대하면 안 돼. Gemini가 3종류의 Workspace 파일과 8개 named format을 만들 수 있다는 건 복사와 재서식 작업을 줄여 준다는 뜻이지, Excel 수식 검산이나 Drive 공유 정책까지 끝내 준다는 뜻은 아니야. 특히 팀 폴더에 저장되는 파일은 내용보다 권한 사고가 더 빨리 퍼질 수 있어.

에이전트 쪽에서는 인증 방식을 먼저 봐야 해. OpenAI Help Center는 앱 연결을 실행한 사람의 계정으로 인증하는 방식과 agent-owned account로 인증하는 방식을 나눠. 공유 계정이나 개인 계정을 잘못 쓰면 다른 사람이 그 계정의 권한으로 작업을 실행할 수 있어. 쓰기 작업은 기본 승인 요청으로 두고, 서비스 계정과 최소 권한을 쓰는 쪽이 안전해.

도입 전에는 네 가지만 확인하면 좋아.

  • 저장 위치: AI가 만든 파일이 기기 다운로드인지 Drive 같은 공유 저장소인지 확인해.
  • 접근 권한: 개인 전용인지, 링크 공유인지, 조직 디렉터리 공개인지 확인해.
  • 실행 권한: 에이전트가 읽기만 하는지, 이메일 발송·시트 편집·캘린더 추가 같은 쓰기 작업까지 하는지 확인해.
  • 감사 방법: 누가 실행했고 어떤 앱 계정으로 인증했는지, 실행 횟수와 변경 이력을 볼 수 있는지 확인해.

통과 비판 검토 검증 출처 5
Workspace를 만능 협업 자동화나 안전한 권한 설계가 끝난 상태로 읽는 오해를 걸렀어.
  • Google 업무 앱 계정, Slack workspace, ChatGPT workspace는 모두 작업 공간을 말하지만 계정, 관리자, 데이터 처리 조건이 달라. 본문은 같은 단어를 한 제품으로 합치지 않았어.
  • Gemini가 파일을 만들고 Drive로 내보낼 수 있어도 내용 검산, 소유권, 공유 링크, 폴더 권한은 별도 확인 대상이야.
  • OpenAI 도움말은 앱 연결 인증을 end-user account와 agent-owned account로 나누고, agent-owned account에는 서비스 계정과 최소 권한을 권장해.
  • 같은 문서는 쓰기 작업이 기본적으로 실행 중 승인 요청으로 설정된다고 안내해. 그래서 본문은 자동 실행보다 승인 지점을 먼저 보게 했어.
  • 지원 플랜에 들어간다는 말과 우리 조직에서 바로 켜진다는 말은 달라. 관리자 설정, RBAC, Slack 승인, 앱 연결 상태가 남아.
  • Workspace는 AI가 업무 파일과 조직 권한을 만나는 경계로 읽는 편이 정확해.
  • 파일 생성보다 중요한 건 누가 보고, 어떤 앱을 쓰고, 어떤 쓰기 작업을 승인해야 하는지야.
