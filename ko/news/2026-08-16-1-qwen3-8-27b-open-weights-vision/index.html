2026-08-16 🔥95점 · 출처 2 원문 Hugging Face — Qwen/Qwen3.8-27B 모델 카드

Qwen3.8-27B 가중치가 Apache 2.0으로 풀렸어, 비전 인코더까지 붙여서

덴스 27B에 64개 레이어, 네이티브 262,144 토큰 컨텍스트, Gated DeltaNet과 Gated Attention을 섞은 구조가 모델 카드에 그대로 적혀 있어. 텍스트 전용으로 예고됐던 모델인데 이미지와 비디오를 받는 인코더가 같이 들어왔고, 컴퓨터 조작 벤치마크 OSWorld-Verified는 84.3이야.

27B 가중치가 Apache 2.0으로 나왔어

Qwen3.8-27B 가중치가 Apache 2.0으로 Hugging Face에 올라왔어. 예고에 없던 비전 인코더까지 같이 붙어서 나왔지.

파라미터 27B를 전부 켜는 덴스 구조야. 일부 전문가만 골라 쓰는 방식이 아니라서, 가중치를 직접 운영할 생각이면 규모를 그대로 계산에 넣어야 해. 지난달 다운로드는 기본 저장소가 91,917건, FP8 저장소가 123,157건으로 찍혀 있어.

텍스트만 받는 모델이 아니야

모델 카드에는 이미지와 비디오를 이해하는 인코더가 포함된다고 적혀 있어. 입력에 화면 캡처나 영상이 들어가고 출력은 텍스트로 돌아오는 구성이야.

컨텍스트는 네이티브 262,144 토큰이고, 확장하면 1,000,000 토큰까지 늘어난다고 적혀 있어. 100만은 기본값이 아니라 상한이니까 사양을 잡을 때 둘을 섞으면 안 돼.

어텐션을 네 블록에 하나만 넣었어

레이어는 64개고, 배치가 좀 특이해. 3 × (Gated DeltaNet → FFN) 다음에 1 × (Gated Attention → FFN)을 놓는 묶음을 16번 반복해.

즉 네 블록 중 세 개는 Gated DeltaNet이 맡고, 일반 어텐션은 한 번만 들어가는 거야. 입력이 길어질수록 부담이 커지는 쪽은 어텐션이니까, 그 비중을 줄여 긴 입력을 감당하려는 배치로 읽혀. 다만 얼마나 줄었는지 잰 수치는 카드에 없어.

모델 카드에 적힌 점수

  • 코딩: SWE-bench Pro 61.7, LiveCodeBench v6 90.3, Terminal Bench 2.1 73.0
  • 지식·지시: GPQA Diamond 89.2, IFBench 79.5
  • 화면 조작: OSWorld-Verified 84.3, AndroidWorld 81.9, WebArena-Verified 64.8

전부 배포자가 자기 저장소에 올린 값이야. 같은 조건으로 다시 잰 제3자 결과는 아직 안 보여. 순위 근거로 쓰기엔 이르고, 어떤 과제를 겨냥한 모델인지 읽는 용도로는 충분해.

직접 올릴지 정할 때 볼 것

  • 화면을 조작하는 자동화를 만든다면: OSWorld-Verified 84.3점처럼 컴퓨터 조작 계열 점수가 앞에 나와 있어. 사내 과제로 한 번 재보고 정할 값이야.
  • 장비를 잡는다면: 덴스라서 27B 전체가 메모리에 올라가. 필요한 VRAM과 처리량은 카드에 없어서 실측이 필요해.
  • 재배포나 파생 모델을 계획한다면: 라이선스가 Apache 2.0으로 적혀 있어 조건을 먼저 확인할 여지가 적어.

급할 건 없어. FP8 저장소가 같이 올라와 있으니 양자화본으로 먼저 감을 잡고 정해도 늦지 않아.

통과 원문 대조
Qwen이 올린 기본 저장소와 FP8 저장소 두 곳의 모델 카드를 각각 열어 라이선스, 구조, 컨텍스트, 점수, 배포 규모를 기사와 맞춰 봤어.
  • 라이선스 대조: 두 저장소 모두 Apache 2.0으로 적혀 있어. 기사에서도 그 표기만 썼어.
  • 구조 대조: 기본 저장소 카드에 덴스 27B, 64개 레이어, `16 × (3 × (Gated DeltaNet → FFN) → 1 × (Gated Attention → FFN))` 반복 구조가 적혀 있어. MoE라고 바꿔 쓰지 않았어.
  • 모달리티 대조: 두 카드 모두 이미지와 비디오를 이해하는 인코더가 포함된다고 적었어. 출력은 텍스트야.
  • 컨텍스트 대조: 네이티브 262,144 토큰이고 최대 1,000,000 토큰까지 늘릴 수 있다고 적혀 있어. 확장 조건은 카드에 붙은 서술 그대로만 옮겼어.
  • 배포 규모 대조: 기본 저장소는 지난달 다운로드 91,917회, FP8 저장소는 123,157회로 표시됐어.
  • 확인 못 한 것: Qwen 공식 블로그의 발표 본문은 페이지가 모델 이름만 반환해 읽지 못했어. 그래서 발표문 문구는 인용하지 않았어.

Qwen이 직접 올린 두 저장소 카드를 따로 열어 숫자가 어긋나지 않는지 봤고, 벤더 밖 재현 자료가 있는지도 찾아봤어.
  • 1차 출처 교차검증: 배포자인 Qwen의 기본 저장소와 FP8 저장소 모델 카드를 각각 직접 열어 라이선스, 컨텍스트 한도, 벤치마크 점수가 같은 값인지 하나씩 맞춰 봤어. SWE-bench Pro 61.7, LiveCodeBench v6 90.3, IFBench 79.5, OSWorld-Verified 84.3, AndroidWorld 81.9가 두 카드에서 동일했어.
  • 독립 재현 확인 실패: 같은 조건으로 이 점수를 다시 측정한 제3자 결과는 찾지 못했어. 그래서 본문에서 점수를 배포자가 올린 값이라고 못 박았어.
  • 두 저장소는 같은 배포자가 올린 문서라 서로를 독립 검증으로 세지 않았어. 값이 어긋나지 않았다는 확인까지만 썼어.
  • 인용 매체 제외: 같은 발표를 옮긴 요약 블로그와 스펙 정리 사이트는 1차 출처가 아니어서 sourceCount에 넣지 않았어.
  • Qwen 공식 블로그 확인 실패: 발표 페이지 본문을 받지 못해 배포 일자와 홍보 문구를 기사에 쓰지 않았어.
통과 수치 검증
본문 수치를 규모, 한도, 점수, 배포량으로 나눠 적고 어느 카드에서 왔는지 표시했어.

  • 262,144 - 네이티브 컨텍스트 토큰 수야.

  • Mechanism evidence: 64개 레이어를 `16 × (3 × (Gated DeltaNet → FFN) → 1 × (Gated Attention → FFN))`로 반복 배치한 구조는 기본 저장소 카드에서 확인했어.

통과 비판 검토
배포자 점수를 검증된 성능으로 옮길 위험과, 27B라는 이름만 보고 장비 사양을 가볍게 잡을 위험을 눌러 봤어.
  • 벤치마크 이해관계 점검: 점수는 전부 Qwen이 자기 저장소에 올린 값이야. 독립 재현 결과가 없다는 문장을 본문 섹션에 남겼어.
  • 구조 오해 점검: 덴스 27B라서 MoE처럼 일부만 켜는 방식이 아니야. 메모리에 27B 전체를 올려야 한다는 조건을 마지막 섹션에 적었어.
  • 라이선스 범위 점검: Apache 2.0은 카드 표기 그대로만 썼어. 상업적 사용 조건을 카드보다 넓게 해석해 쓰지 않았어.
  • 최상급 표현 점검: 최강, 최초, 압도 같은 표현은 쓰지 않았어. 점수도 출처를 붙여 적었어.
  • 제품 범위 점검: 이 기사는 27B 가중치 공개만 다뤘어. 2.4조 파라미터 Qwen3.8-Max의 가중치가 같이 나왔다고 쓰지 않았어.
  • 컨텍스트 과장 점검: 100만 토큰은 확장 상한이라 기본값과 구분해 적었어.
  • 위험: 27B 가중치 공개를 Qwen3.8-Max 가중치 공개로 읽을 수 있었어. 조치: 제목과 본문에서 모델명을 Qwen3.8-27B로 고정하고 Max를 언급하지 않았어. 수정 완료.
  • 위험: 100만 토큰이 기본 컨텍스트로 읽힐 수 있었어. 조치: 네이티브 262,144 토큰과 확장 상한을 나눠 적었어. 수정 완료.
  • 미해결: 모델 카드 점수를 같은 조건으로 재현한 독립 시험은 확인하지 못했어. 도입 판단에는 사내 과제로 다시 재는 절차가 필요해.
  • 미해결: 실행에 필요한 VRAM과 처리량은 카드에 없어서, 어떤 GPU 구성이면 되는지는 이 기사만으로 정할 수 없어.
