2026-08-18 🔥78점 · 출처 3 원문 OpenAI Developer Community — Developer Mode 문서와 커스텀 MCP 동작이 다르다는 보고

ChatGPT에 커스텀 MCP를 켜면 같은 대화에서 Gmail·캘린더가 막혀

OpenAI 도움말은 한 프롬프트에서 자사 앱과 외부 앱을 함께 부를 수 있다고 적어놨는데, 실제로는 FORBIDDEN: This conversation is restricted to developer MCPs가 떠. 6월 16일 OpenAI 직원은 성능보다 안전을 택한 의도된 동작이라고 답했고, 8월 17일 올라온 재현 보고에서도 그대로였어.

문서엔 여러 앱을 한 프롬프트에서 부를 수 있다고 적혀 있어

ChatGPT에 커스텀 MCP를 켜면 같은 대화에서 Gmail과 캘린더 호출이 막혀.

MCP는 ChatGPT 같은 모델에 외부 도구를 붙이는 연결 규약이야. Developer mode를 켜면 직접 만든 MCP 서버를 커넥터로 등록할 수 있고, Pro·Plus·Business·Enterprise·Education 계정에서 웹으로 쓸 수 있어.

OpenAI 도움말에는 combine apps for complex orchestrations가 된다고 적혀 있어. 자사 앱과 외부 앱을 한 프롬프트에서 같이 부르는 예시까지 붙어 있고.

실제로는 개발자 MCP만 남고 나머지가 잘려

보고된 메시지는 FORBIDDEN: This conversation is restricted to developer MCPs야.

8월 17일 올라온 재현 기록이 범위를 좁혀 놨어. ChatGPT Pro에서 GPT-5.6에 Extra High 컨텍스트, 커스텀 MCP 하나를 켠 상태였는데 Gmail과 Google 캘린더, Google 연락처가 전부 같은 메시지로 막혔어.

대화가 통째로 죽는 건 아니야. 그 사이에도 개발자 MCP는 앞뒤로 잘 돌았거든. 커스텀 MCP를 켠 대화에서 내장 앱만 골라 잘리는 동작이야.

6월에 나온 답은 버그가 아니라 의도라는 거였어

같은 증상은 6월 12일에 이미 올라와 있었어. 그때 보고자는 OpenAI 지원이 케이스 09461958에서 커스텀 커넥터와 내장 앱 사이에 상호운용을 보장하지 않는다고 답했다고 적었어.

6월 16일에는 다른 보고자가 DesktopCommander를 켠 뒤 Coda와 Google 캘린더를 같은 대화에서 못 썼다고 했어. 같은 날 OpenAI 직원 답변이 달렸는데, 이건 성능보다 안전을 앞에 둔 의도된 동작이라는 설명이었어. 대안으로는 Codex를 들었고.

두 달 뒤에도 같은 메시지가 재현됐고, 도움말 문구가 이 제약에 맞춰 고쳐졌다는 기록은 찾지 못했어.

자동화를 설계하기 전에 확인할 것

  • 한 대화에 하나만: 커스텀 MCP를 켠 대화에서는 내장 앱을 부르지 않는다고 잡는 게 안전해. 내부 데이터를 가져와서 캘린더에 넣는 흐름은 대화를 나눠야 돌아가.
  • 문서를 설계 근거로 쓰지 않기: 도움말에 적힌 오케스트레이션 예시는 커스텀 MCP가 없는 대화 기준으로 읽는 게 맞아. 문서만 보고 스펙을 짜면 구현 단계에서 어긋나.
  • 에이전트를 옮길 곳: OpenAI 직원이 든 대안은 Codex야. 도구를 여러 개 엮어야 하는 작업이면 ChatGPT 대화보다 그쪽이 제약이 적어.
  • 아직 안 밝혀진 것: 언제부터 이렇게 동작했는지, 앞으로 풀 계획이 있는지는 공개된 기록이 없어. 지원 케이스 내용도 보고자가 옮긴 말이라 원문으로는 확인이 안 돼.

사내 데이터를 붙인 커스텀 커넥터로 업무 자동화를 짜는 팀이라면 지금 설계를 한 번 볼 만해. 앱 하나만 쓰거나 도구 없이 대화만 하는 경우엔 달라지는 게 없어. 급할 건 없고, 대화를 나누는 정도로도 대부분 돌아가니까.
