llm-anthropic 0.27, Anthropic SDK 1 요구

llm-anthropic 0.27은 anthropic 1.x와 Python 3.10 이상을 요구해. 이 범위의 Anthropic SDK v1 전환에서는 HTTP 계층이 httpx2로 바뀌어, 직접 만든 httpx 클라이언트·전송 계층이나 httpx를 패치하는 관측·목킹 도구를 쓰는 팀은 업그레이드 전에 해당 경로부터 바로 점검해야 해.

llm-anthropic 0.27은 Anthropic SDK 1.x를 요구해

LLM CLI에서 Anthropic 모델을 연결하는 파이썬 플러그인 llm-anthropic(GitHub) 0.27은 anthropic>=1,<2를 요구해. PyPI의 0.27 메타데이터에는 llm>=0.33, Python >=3.10도 함께 적혀 있고, 릴리스 노트는 “Upgraded to anthropic>=1”이라고 밝혔어. 이 변화는 모델 성능이 아니라 SDK와 HTTP 계층의 호환 범위를 바꾸는 일이라, 직접 만든 httpx 클라이언트·전송 계층이나 httpx를 패치하는 관측·목킹 도구를 쓰는 팀은 업그레이드 전에 그 경로부터 바로 점검해야 해.

먼저 확인할 설치 경로

이제 Python 3.10 이상이 필요해. 먼저 잠금 파일이나 의존성 해석 결과에서 anthropic>=1,<2와 llm>=0.33이 함께 풀리는지 확인하면 돼. 팀이 가상환경을 새로 만들지 않고 잠금 파일만 갱신하는 편이라면, 이 단계에서 바로 설치 실패나 버전 충돌을 먼저 볼 수 있어.

httpx2 전환은 쓰는 코드에 따라 갈려

Anthropic의 v1 마이그레이션 문서는 SDK HTTP 계층이 httpx에서 httpx2로 옮겨갔다고 설명해. 0.27이 요구하는 anthropic>=1,<2가 이 v1 업그레이드 범위와 같아서, 이번 플러그인 업데이트를 올릴 때 이 전환도 함께 확인해야 해.

  • 숫자 값만 넘기는 경우: timeout=30.0, max_retries=3처럼 평범한 값만 넘겼다면 문서는 바꿀 일이 없을 가능성이 높다고 적어.
  • httpx 객체를 직접 넘기는 경우: httpx.Client, transport, httpx.Timeout을 SDK에 넘겼다면 httpx2에서 만든 객체로 바꿔야 해. 문서는 이전 httpx.Client 또는 AsyncClient를 http_client=에 넘기면 생성 시 TypeError가 난다고 직접 적어 놨어.
  • 관측·목킹 도구를 거는 경우: httpx 자체를 패치하는 관측·목킹 도구는 SDK 요청을 조용히 놓칠 수 있어. 문서는 애플리케이션 시작점에서 httpx2.alias_httpx()를 한 번 실행해 import httpx가 httpx2를 가리키게 하는 방법을 제시해.

업그레이드 전에 확인할 조건

  • 숫자형 옵션만 쓴다면: 잠금 파일을 다시 풀고, 격리된 가상환경에서 anthropic>=1,<2, llm>=0.33, Python 3.10 이상이 함께 설치되는지 확인해.
  • 커스텀 httpx 객체나 패치형 도구를 쓴다면: httpx2로 import와 객체를 옮기거나, 애플리케이션 시작점에서 httpx2.alias_httpx()를 실행할 수 있는지 먼저 확인해. 라이브러리 자체가 이 별칭을 사용자 대신 실행하면 안 된다는 제한도 문서에 있어.

통과 비판 검토
플러그인 의존성 변경을 모든 사용자에게 같은 작업으로 일반화하지 않도록, 문서가 밝힌 적용 조건을 분리했어.
  • 범위 고정: Claude 모델이나 API 성능 변화가 아니라 llm-anthropic 0.27의 SDK 의존성 범위와 v1 HTTP 전환만 다뤄.
  • 영향 구분: 평범한 숫자형 timeout·재시도 값만 넘기는 코드는 대체로 그대로지만, httpx 객체를 SDK에 넘기거나 SDK가 돌려주는 HTTP 객체를 검사하는 코드는 점검해.
  • 실패 방식: 이전 httpx.Client 또는 AsyncClient를 http_client로 넘기면 생성 시 TypeError가 나며, httpx를 패치하는 관측·목킹 도구는 SDK 요청을 보지 못할 수 있어.
  • 직접 근거: MIGRATION.md는 `Passing an httpx.Client / httpx.AsyncClient ... raises a TypeError`라고 쓰고, 별도로 `call httpx2.alias_httpx() once at start-up instead`를 제시해.
  • Causal evidence: Anthropic v1 문서가 httpx2 전환 → 오래된 httpx.Client 전달 시 TypeError → httpx 패치형 도구의 요청 관측 중단이라는 코드 경로를 각각 분리해 적어 놨어.
  • 유의점: v1 전환이 있어도 숫자형 timeout·재시도 값만 쓰는 코드는 바꿀 것이 없을 수 있어. 조치: 커스텀 객체와 관측·목킹 도구가 있는 경우로 점검 범위를 한정했어.
