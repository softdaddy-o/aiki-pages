Boris Cherny, Claude Code 팀을 5가지 역할로 나눴어

Prototyper, Builder, Sweeper, Grower, Maintainer라는 구분은 직무명이 아니라 제품 단계별로 필요한 실행 방식에 가까워. 새 제품은 1·2·3번, 성장 제품은 2·3·4번, 강한 PMF 이후에는 3·4·5번 비중이 커진다는 식이라 팀 구성 판단에 바로 쓸 수 있어.

무슨 일이 일어났나

Claude Code 쪽 Boris Cherny가 Claude Code 팀을 보며 앞으로 제품팀 역할이 어떻게 바뀔지 적었어. 핵심은 직무명이 아니라 실행 역할이야. 그는 Prototyper, Builder, Sweeper, Grower, Maintainer 5개 archetype을 제시했고, 한 사람이 2개나 3개 역할을 넘나드는 경우가 많다고 봤어.

5가지 역할은 뭐가 다른가

Prototyper는 새 아이디어를 많이 내고, Builder는 그 아이디어를 실제 제품이나 인프라로 바꿔. Sweeper는 UI와 코드, 시스템을 정리하고 안 맞는 기능을 걷어내. Grower는 이미 만들어진 제품을 PMF에 맞게 다듬고, Maintainer는 성숙한 시스템을 안전하고 빠르게 유지해. 이 구분이 흥미로운 건 “PM”, “디자이너”, “엔지니어” 같은 명함보다 실제로 어떤 일을 밀고 있느냐를 먼저 본다는 점이야.

제품 단계별로 달라지는 조합

Cherny가 보는 건강한 팀은 제품 단계에 따라 조합이 달라져.

  • 새 제품·pre-PMF: 1+2+3, 즉 많이 만들고 바로 제품화하고 군더더기를 치우는 사람이 필요해.
  • 성장 중인 제품: 2+3+4에 일부 5가 붙어야 해. 만드는 힘보다 개선과 안정화가 중요해져.
  • 강한 PMF 이후: 3+4+5가 중심이고, 필요할 때만 Builder가 들어와.

어떻게 써먹어야 하나

이걸 채용 직무표로 그대로 옮기면 안 맞을 수 있어. AI agent와 코딩 도구를 깊게 쓰는 Claude Code 같은 팀이라 가능한 부분도 있거든. 그래도 팀을 볼 때 질문은 바꿔볼 만해. “PM이 있나, 디자이너가 있나”보다 “지금 우리 제품 단계에 필요한 실행 역할이 비어 있나”를 먼저 보는 거야. 특히 작은 팀이라면 한 사람이 2~3개 역할을 맡는 게 예외가 아니라 기본값이 될 수 있어.
