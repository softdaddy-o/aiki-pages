Mistral이 Shieldstral 3B 안전 분류기를 Apache 2.0으로 공개했어

지난주까지 arXiv 논문으로만 있던 모더레이션 모델이 이번엔 Hugging Face에 가중치로 올라왔어. BF16으로 올리면 16GB VRAM 한 장에 들어가고, 판정 정책을 평문으로 적어 넣으면 재학습 없이 기준이 따라 움직여. 한국어를 포함해 12개 언어를 받고, HarmBench 프롬프트 분류에서 F1 99.4%가 나왔어.

논문이던 게 내려받을 수 있는 가중치가 됐어

“지난주까지는 읽을 수만 있었는데, 이번엔 내려받아 돌릴 수 있어.”

Shieldstral-1.0-3B는 걸러낼 기준을 평문 문장으로 받아서 글과 이미지가 그 기준을 어겼는지 판정하는 3B 크기의 멀티모달 안전 분류기야. 글을 만들어 내는 모델이 아니라, 올라온 내용을 검사하는 판정기지.

Mistral이 8월 4일 이 가중치를 Apache 2.0으로 공개했어. Hugging Face에서 바로 내려받고, BF16으로 올리면 16GB VRAM 한 장에 들어가.

같은 모델의 arXiv 논문은 7월 30일에 나왔고, 그때 한 번 다뤘어. 그때는 방법과 점수뿐이었고, 이번엔 라이선스와 실행 조건이 붙었어.

정책을 평문으로 넣는 방식이야

기존 가드 모델은 위험 분류 체계가 학습 단계에서 굳어져. 회사 정책이 바뀌면 다시 학습시켜야 했거든.

Shieldstral은 판정할 정책을 평문 문장으로 같이 넣어. 모더레이션을 “이 내용이 이 정책을 어겼나”라는 예/아니오 한 문제로 바꿔서, 한 번의 forward pass로 보정된 안전 점수를 돌려줘. 텍스트만이 아니라 이미지, 그리고 텍스트와 이미지를 같이 받는 멀티모달 판정도 돼.

정책 문구만 고쳐도 판정 기준이 따라 움직인다는 게 여기서 나오는 차이야.

같은 크기대에서 어디까지 나왔나

  • 프롬프트 안전 분류: HarmBench F1 99.4%, WildGuardTest 88.1%
  • 멀티모달 안전: VLGuard 97.7%, UnsafeBench 81.8%
  • 비교 대상: GPT-OSS-Safeguard-20B, LlamaGuard-4-12B, ShieldGemma-9B, Qwen3Guard-8B

네 모델 모두 가중치가 공개된 안전 분류 전용 모델이야. 같은 자리에 놓고 재보려고 고른 비교군이고, 3B인 Shieldstral보다 전부 크다는 게 이 표의 조건이야.

Mistral은 자기 크기의 최대 7배까지 큰 오픈 가드 모델과 비슷하거나 더 나은 결과를 냈다고 적었어. 다만 이 표는 Mistral이 직접 돌린 자체 평가라는 건 감안하고 봐야 해. 제3자가 재현한 평가는 아직 안 보여.

모더레이션을 옮길지 보는 팀이 확인할 것

  • 언어: 지원 목록에 한국어가 들어 있어. 영어, 프랑스어, 중국어를 포함해 12개 언어야. 한국어만 따로 떼어 낸 점수는 문서에 없어.
  • 실행 스택: vLLM을 권장하고, llama.cpp와 Transformers로도 돌아가. 기존 추론 서버에 얹어 볼 수 있어.
  • 정책 운영: 정책이 자주 바뀌는 서비스라면 재학습 대기 시간이 사라지는 게 실제 이득이야.
  • 책임 경계: 라이선스가 열려 있어도 오탐과 미탐은 도입한 팀이 감당해. 사내 데이터로 한 번 재보고 판단해도 늦지 않아.

Mistral 발표문과 Hugging Face 모델 카드를 각각 열어 라이선스, 크기, 실행 조건, 지원 언어, 벤치마크 수치를 대조했어.
  • 발표 날짜 대조: Mistral 발표문의 게시일이 2026년 8월 4일인 걸 확인했어.
  • 모델명 대조: 발표문과 모델 카드 모두 Shieldstral-1.0-3B로 적혀 있어. 3B 규모의 open-weights 멀티모달 안전 분류기야.
  • 라이선스 대조: 발표문과 모델 카드 양쪽에서 Apache 2.0 라이선스를 확인했어.
  • 베이스 모델 대조: 모델 카드에 Ministral-3-3B-Base-2512에 Pixtral 비전 인코더를 붙였다고 적혀 있어.
  • 실행 조건 대조: 발표문은 단일 16GB NVIDIA GPU에서 돌아간다고 적었고, 모델 카드는 BF16에서 16GB VRAM에 들어간다고 적었어.
  • 정책 입력 방식 대조: 발표문이 추론 시점에 평문 정책을 받아 재학습 없이 판정한다고 적은 걸 확인했어.
  • 지원 언어 대조: 모델 카드에 영어, 프랑스어, 스페인어, 독일어, 이탈리아어, 포르투갈어, 네덜란드어, 중국어, 일본어, 한국어, 아랍어, 러시아어가 나열돼 있어.
  • 실행 스택 대조: 모델 카드가 vLLM 권장, llama.cpp, Hugging Face Transformers를 적어 둔 걸 확인했어.
  • 확인 못 한 것: 학습 데이터 규모와 학습 비용은 이번 발표문과 모델 카드에 없어서 본문에 쓰지 않았어.
통과 교차 검증 검증 출처 2
벤더 발표문과 배포처 모델 카드를 서로 다른 문서로 나눠 읽고, 발표 문구가 아니라 배포 문서에 실제로 적힌 조건으로 본문 수치를 맞췄어.
  • 1차 출처 교차검증: Mistral 공식 발표문과 Hugging Face 모델 카드를 따로 열어 라이선스, 16GB 실행 조건, 지원 언어, 벤치마크 표를 각각 확인했어. 발표문에 없던 언어 목록과 세부 점수는 모델 카드에서만 확인돼.
  • 선행 보도 분리: 같은 모델의 arXiv 논문은 2026년 7월 30일자 기사로 이미 다뤘어. 이번 건은 논문이 아니라 가중치와 라이선스가 붙은 배포라, 겹치는 방법 설명 대신 배포 조건만 남겼어.
  • 교차로 세지 않은 것: 같은 발표를 옮긴 요약 계정과 커뮤니티 글은 독립 출처로 세지 않았어. sourceCount는 발표문, 모델 카드, 선행 arXiv 논문 3건이야. 이번 배포 조건을 확인한 문서는 앞의 2건이고, arXiv 논문은 7월 30일 선행 공개를 뒷받침하는 출처야.
  • 확인 실패: 제3자가 이 벤치마크 표를 재현한 독립 평가는 찾지 못했어. 그래서 본문에 Mistral 자체 평가라고 적었어.
  • Causal evidence: 정책을 추론 시점 입력으로 받는 구조라 정책 문구를 고치면 재학습 없이 판정 기준이 움직인다는 인과는 Mistral 발표문의 policy-adaptive 설명에서 확인했어.

본문에 쓴 수치가 크기인지 점수인지 실행 조건인지 갈라 적고, 각각 어느 문서에서 왔는지 표시했어.
  • 3B - Shieldstral-1.0-3B의 파라미터 규모야. 베이스는 Ministral-3-3B-Base-2512로 모델 카드에 적혀 있어.
  • Apache 2.0 - 가중치에 붙은 라이선스야. 발표문과 모델 카드 양쪽에 있어.
  • 16GB - BF16으로 올릴 때 필요한 VRAM이야. GPU 한 장 기준이야.
  • 12개 - 모델 카드에 나열된 지원 언어 수야. 한국어가 포함돼 있어.
  • 99.4% - HarmBench 프롬프트 안전 분류 F1이야. 모델 카드 표 수치야.
  • 88.1% - WildGuardTest 프롬프트 안전 분류 F1이야.
  • 97.7% - VLGuard 멀티모달 안전 F1이야.
  • 81.8% - UnsafeBench 멀티모달 안전 F1이야.
  • 7배 - 발표문이 적은 비교 범위야. 자기 크기의 최대 7배까지 큰 오픈 가드 모델과 견줬다는 뜻이야.
  • 20B, 12B, 9B, 8B - 비교 대상 모델 이름에 붙은 크기야. GPT-OSS-Safeguard-20B, LlamaGuard-4-12B, ShieldGemma-9B, Qwen3Guard-8B 순서야.
  • 8월 4일 - Mistral 발표문 게시일이야. 7월 30일은 같은 모델의 arXiv 논문을 다룬 앞선 기사 날짜야.
  • Mechanism evidence: 한 번의 forward pass로 보정된 안전 점수를 돌려준다는 동작은 발표문의 single forward pass 서술에서 확인했어.
  • 출처 경계: 위 벤치마크 수치는 전부 Mistral 발표문과 Hugging Face 모델 카드에 적힌 자체 평가 값이야. 제3자가 독립적으로 재현한 수치가 아니야.
  • 확인 못 한 수치: 지연 시간, 처리량, 학습 표본 수는 이번 발표문과 모델 카드에 없어서 쓰지 않았어.
통과 비판 검토
벤더 자체 평가를 독립 검증으로 옮겨 읽을 위험과, 논문 기사와 겹쳐 같은 뉴스를 두 번 쓰는 위험을 눌러 봤어.
  • 출처 이해관계 점검: 벤치마크 표는 전부 Mistral이 직접 돌린 평가야. 본문에 자체 평가라고 적고 사내 데이터 재검증을 권했어.
  • 중복 보도 점검: 같은 모델의 논문은 이미 다뤘어. 이번 기사에서는 방법 설명을 빼고 라이선스, 실행 조건, 지원 언어처럼 배포 시점에 새로 생긴 정보만 남겼어.
  • 체리피킹 점검: 높은 점수만 뽑지 않도록 멀티모달에서 상대적으로 낮은 UnsafeBench 81.8%도 같이 적었어.
  • 최상급 표현 점검: 업계 최초, 최고 같은 표현은 쓰지 않았어. 7배 비교도 발표문 문구 그대로 범위만 옮겼어.
  • 적용 범위 점검: 안전 분류기는 생성 모델이 아니라 판정기야. 성능 좋은 범용 모델처럼 읽히지 않게 용도를 첫 섹션에 적었어.
  • 라이선스 점검: Apache 2.0은 상업적 사용을 막지 않아. 다만 모더레이션 판정 책임은 도입한 쪽에 남는다는 걸 마지막 섹션에 적었어.
  • 위험: 벤치마크 수치가 독립 검증된 것처럼 읽힐 수 있었어. 조치: 본문에서 Mistral 자체 평가라고 명시하고, 사내 데이터로 재측정하라는 문장을 마지막 섹션에 넣었어. 수정 완료.
  • 미해결: 제3자 재현 평가를 찾지 못했어. 점수 자체는 아직 벤더 표에만 기대고 있어.
  • 미해결: 한국어 안전 분류 성능만 따로 떼어 낸 수치는 문서에 없어. 지원 언어 목록에 있다는 것까지만 확인돼.
  • 수치가 틀렸을 때: 벤치마크가 재현되지 않더라도 이 기사에서 남는 판단 근거는 Apache 2.0 라이선스, 16GB 단일 GPU 실행, 평문 정책 입력이야. 이 세 가지는 배포 문서만으로 서 있어.
